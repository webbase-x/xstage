# X-Stage Karaoke Windows v0.9.48 — แก้หน้าต่าง X-Stage Online ซิงค์ (Step 1 / Google Login)

**สถานะ:** ซอร์สสำหรับ Build บน Windows 11 — ไม่ใช่ EXE พร้อมติดตั้ง และไม่ได้แก้ไขข้อมูลเพลงที่มีอยู่

## สาเหตุที่ตรวจพบจากซอร์สจริง

1. **ขั้นตอนที่ 1 แสดงข้อมูลซ้ำ:** UI พิมพ์จำนวนเพลง `ตรวจแล้ว x/y` ทั้งในบรรทัดหัวเรื่องและบรรทัดความคืบหน้า จึงดูเหมือนเป็น 2 รายการที่ซ้ำกัน ทั้งที่มีเพียง 1 งานตรวจฐานข้อมูล
2. **หลังกดซิงค์ข้อความหยุดนิ่ง:** ระหว่างตรวจ SF2/FFmpeg, เปิดเบราว์เซอร์ยืนยัน Google และอ่านรายการจาก Drive โค้ดส่งข้อความขั้นตอนเพียงครั้งเดียว; เมื่อไม่มีตัวเลข `done/total` จะแสดง `กำลังเชื่อมต่อ / เตรียมขั้นตอนถัดไป…` โดยไม่ระบุสาเหตุหรือเวลาที่ผ่านไป Google OAuth ต้องรอผู้ใช้ยืนยันในเบราว์เซอร์ (เดิมรองรับการรอสูงสุด 180 วินาที)
3. **แถบความคืบหน้าแสดงเหมือนเริ่มใหม่หลังตรวจสำเร็จ:** เมื่อจบขั้นตอนตรวจฐาน ค่า progress ถูกรีเซ็ตเป็น 0 แม้ทำงานเสร็จแล้ว
4. **ข้อความสำเร็จถูกทับ:** หลังซิงค์เสร็จ UI กลับไปเรียก `update_selection()` และเขียน `เลือกประเภทเพลงแล้วกดซิงค์` ทับข้อความสรุปผล

## สิ่งที่แก้

- แยกข้อมูลของแต่ละบรรทัดให้มีหน้าที่ชัดเจน: **ชื่อขั้นตอน** / **รายละเอียดที่กำลังดำเนินการ** / **จำนวนและเปอร์เซ็นต์พร้อมเวลาที่ผ่านไป** ไม่พิมพ์ตัวเลขเดิมซ้ำสองแถว
- ตรวจจำนวนฐานข้อมูลด้วยเงื่อนไข visibility เดียวกับการสแกนจริง เพื่อให้เปอร์เซ็นต์สัมพันธ์กับงานจริง
- แสดงความคืบหน้าขั้นตอนที่ 1 แบบ progress bar; เมื่อเสร็จแสดง 100% และจำนวนชนิดเพลงที่พร้อมซิงค์
- แบ่งงานเป็น 5 ระยะ: (1) ตรวจฐานเพลง (2) ตรวจ SoundFont/FFmpeg (3) ยืนยันบัญชี Google (4) ตรวจ/ซิงค์ไฟล์เพลง (5) เผยแพร่ฐานข้อมูลเว็บ
- ระหว่างขั้นตอนที่ยังวัดเปอร์เซ็นต์ไม่ได้ แสดงแถบวิ่ง, จุดขยับ และ **ตัวนับวินาทีที่เปลี่ยนจริง** โดยไม่แต่งเปอร์เซ็นต์ขึ้นมา; เมื่อเงียบนาน 30 วินาที จะแจ้งให้ตรวจเบราว์เซอร์/เครือข่าย และยังมีปุ่มหยุด
- เมื่อเสร็จ ผิดพลาด หรือยกเลิก ให้แสดงข้อความผลลัพธ์ค้างไว้ ไม่ถูกข้อความเริ่มต้นทับ
- รักษาฟังก์ชันปิด–เปิดหน้าต่างใหม่ หยุด/เริ่มซิงค์ซ้ำ กรอง NCN/MIDI การเลือก SoundFont และ Build Gate เดิม
- ยกเลิก timer ของ progress bar เมื่อปิดหน้าต่าง ลดคำเตือน Tk callback ค้าง

## ขอบเขตและข้อจำกัด

- การที่ตัวนับเวลาเคลื่อนไหวหมายถึง **UI ยังตอบสนอง** ไม่ได้ยืนยันว่า Google เชื่อมต่อสำเร็จ หาก Google ยังคงรอสิทธิ์/เน็ตไม่ตอบ ต้องใช้หน้าต่างเบราว์เซอร์ให้สำเร็จหรือกดหยุด แล้วดูข้อความผิดพลาด
- ไม่แก้การอนุญาต OAuth ของ Google ไม่อัปโหลดไฟล์เพลงไปสาธารณะ ไม่เก็บโทเค็นเป็นไฟล์ ไม่ยกเลิก Test Gate และไม่แตะฐานเพลงจริง
- ไม่ได้ Build EXE/ทดสอบการเชื่อมต่อ Google กับบัญชีจริงบน Windows จากสภาพแวดล้อมนี้

## วิธีนำไปใช้บน Windows

**ตัวเลือก A: Full Source ZIP (แนะนำ)**

1. ปิด X-Stage Karaoke ที่ใช้งานอยู่
2. แตก ZIP `X-Stage-Karaoke-v0.9.48-Windows-Source-SyncProgress-Fixed.zip` ทั้งไฟล์ลงโฟลเดอร์ใหม่ ไม่รันจากภายใน ZIP
3. รัน `Verify-Windows-0948.cmd` ให้ผ่านทุก Test Gate ก่อน
4. ถ้าผ่านจึงรัน `Build-Windows.cmd` และทำตามวิธีติดตั้งของชุดนั้น หลีกเลี่ยงติดตั้งทับโปรแกรมเดิมจนกว่าจะสำรองฐานและเพลงเดิมเรียบร้อย
5. เปิด **X-Stage Karaoke Online → ซิงค์** ดูขั้นตอน 1/5 จนถึง 5/5 หากค้างที่ 3/5 ให้เปิดเบราว์เซอร์เพื่อยืนยัน Google

**ตัวเลือก B: Patch ZIP สำหรับผู้มีซอร์ส v0.9.48 BuildGate-Fixed อยู่แล้ว**

- แตก `XStage-v0.9.48-Online-Progress-Hotfix-Patch.zip` ทับ **โฟลเดอร์ซอร์สที่แตกแล้ว** ให้ไฟล์ใต้ `karaoke/` และ `tests/` อยู่ตำแหน่งเดิม
- ชุด Patch นี้เปลี่ยนเฉพาะส่วนหน้าต่างซิงก์และเพิ่มชุดทดสอบ ไม่แก้การทดสอบเวอร์ชันเดิม
- จากนั้นทำข้อ 3–5 ด้านบน

## ผลทดสอบ

- Pure Python + Web/Google sync regression: **29 รายการ** ผ่านทั้งหมดที่รัน ข้าม 2 เฉพาะ GUI ที่ไม่ได้เปิดไว้
- GUI regression บน Xvfb: **19 รายการผ่าน**, ครอบคลุมการแสดงข้อมูลขั้นตอน 1, heartbeat ระหว่างรอ Google, ยกเลิกงาน, เริ่มซิงค์ใหม่, ปิด–เปิดหน้าต่าง
- การรันชุดทดสอบทั้งหมดบน Linux ไม่เสร็จภายในเวลาที่กำหนด (บางส่วนอาศัย Windows GUI/อุปกรณ์จริง) จึง **ห้ามถือว่า Windows Build Gate ผ่าน** จนกว่าจะทดสอบบน Windows ตามข้อ 3

เมื่อทดสอบบนเครื่องจริง หากยังค้าง ให้ส่งภาพหน้าต่างที่มีชื่อขั้นตอนและเวลาที่ผ่านไป พร้อม log จาก `Verify-Windows-0948.cmd` หรือ `build-tests-summary.json` **ห้ามส่ง OAuth Client Secret หรือ Access Token**
