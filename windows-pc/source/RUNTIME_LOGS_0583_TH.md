# 0.5.83 — บันทึกข้อผิดพลาดและอาการค้าง

ไฟล์อยู่ที่ `%LOCALAPPDATA%\XStageKaraoke\Logs` เปิดได้จากปุ่ม “เปิดโฟลเดอร์ Log” ในหน้าซาวด์ฟอนต์ หรือวางตำแหน่งนี้ในช่องที่อยู่ของ File Explorer

- XStageKaraoke.log: รุ่นโปรแกรม, Session, เปิด/ซ่อน/ปิดหน้าซาวด์ฟอนต์, อ่านรายการเสียง, โหลด/ปิดเสียงทดลอง, traceback ของข้อผิดพลาด UI และงานเบื้องหลัง หมุนไฟล์เมื่อถึง 5 MB เก็บย้อนหลัง 3 ไฟล์
- XStageKaraoke-native-<session>.log: Python stack ของทุก thread เมื่อ UI ไม่ตอบสนองเกิน 15 วินาที และข้อผิดพลาด native ที่ Python faulthandler รองรับ เก็บไฟล์ล่าสุดประมาณ 10 session แต่ละครั้งบันทึกอาการค้างสูงสุด 3 ครั้ง
- SESSION_END หมายถึงออกจาก mainloop ผ่านขั้นตอนปิดตามปกติ การไม่มีบรรทัดนี้เพียงอย่างเดียวไม่ยืนยันว่าโปรแกรมล้ม เพราะอาจยังเปิดอยู่หรือถูกสั่ง End task

หากเกิดปัญหา ให้จดเวลาที่เกิดและปุ่มที่กด แล้วส่ง XStageKaraoke.log, XStageKaraoke.log.1 (ถ้ามี) และ XStageKaraoke-native-*.log ของ session นั้น ไม่ต้องส่ง SoundFont ขนาดใหญ่

หน้าต่างที่ถูกซ่อนหรือย่อจะปล่อย modal grab ของตัวเองเพื่อไม่ล็อกการคลิกหน้าหลัก เมื่อเรียกเมนูอีกครั้งจะนำหน้าต่างเดิมกลับมา การสร้างหน้าต่างล้มเหลวจะเก็บ traceback และทำความสะอาดหน้าต่างที่สร้างไม่ครบ

ระบบแจ้งข้อผิดพลาด UI/worker ได้เมื่อ event loop ยังตอบสนอง ระหว่างค้างจริงไม่สามารถแสดงกล่องเตือนจาก UI ได้ ไฟล์ stack ช่วยระบุจุดค้าง แต่ไม่รับประกันจับทุกกรณี เช่น DLL ยึด GIL, เครื่องดับ, ระบบปฏิบัติการค้าง หรือถูกบังคับปิดทันที

รายงานเก็บในเครื่องเท่านั้น ไม่มีการส่งเซิร์ฟเวอร์อัตโนมัติ Traceback อาจมีพาธชื่อผู้ใช้หรือชื่อไฟล์ ควรตรวจข้อมูลก่อนส่งให้ผู้อื่น การส่งเซิร์ฟเวอร์ในอนาคตต้องเพิ่มการกรองข้อมูลและตัวเลือกยินยอม

การทดสอบ Windows จริงที่ยังต้องทำ: เปิด/ปิดหน้าซาวด์ฟอนต์, ย่อแล้วเรียกใหม่, ไฟล์ SF2 ขนาดใหญ่, ทดลองเสียงและปิดระหว่างโหลด, ตรวจ Log หลังเกิดอาการซ้ำ

## เพิ่มใน 0.5.85

คลิกขวา → เครื่องมือ → บันทึกเหตุการณ์ / ข้อผิดพลาด (Log)… เลือกไฟล์แล้วอ่านได้ทันที กดรีเฟรชเพื่อดูข้อมูลล่าสุด แสดงท้ายไฟล์สูงสุด 256 KB เพื่อไม่โหลด Log ทั้งก้อน
ไฟล์หลักรวมเหตุการณ์เพื่อไล่เวลาข้ามระบบได้ และมีหมวด SYSTEM / PLAYER / SOUNDFONT / EQ / AUDIO / RECORDING / REMOTE ตามต้นทางของข้อความที่ระบบบันทึก ไฟล์ native ยังคงแยกเฉพาะ stack ของการค้างและ native crash ไม่ได้บันทึกทุกการขยับเมาส์หรือโน้ต MIDI
