# X-Stage Karaoke Windows – Google Drive Preflight Recovery R4

พื้นฐาน: Windows Source v0.9.48 + Recovery R2 + OAuth Discovery R3

## อาการในภาพจากผู้ใช้

- แสดง "✓ เชื่อมต่อ Google Drive แล้ว" แปลว่า OAuth/การจำบัญชีสำเร็จแล้ว **ไม่ต้องล็อกอินใหม่**
- อยู่ขั้นตอนที่ 4/5 "ยืนยันบัญชีแล้ว • กำลังตรวจรายการเดิมใน Google Drive ..." นาน 73 วินาที
- ภาพเพียงภาพเดียว **ยังพิสูจน์ไม่ได้ว่าโปรแกรมค้าง** เพราะโค้ดรุ่นก่อนแสดงข้อความขั้นตอน 4 ก่อนดึงข้อมูล Drive และก่อนสแกนไฟล์เพลงในเครื่องจำนวนมาก และไม่มีรายงานสถานะย่อยจากช่วงดังกล่าว

## สิ่งที่แก้ใน R4

1. ค้นหาโฟลเดอร์ XStageWeb ด้วย Drive query จำกัดชื่อโฟลเดอร์ แทนการดึงรายการทุกไฟล์ใน root
2. ส่งสถานะจริงเป็นลำดับ: หาโฟลเดอร์ XStageWeb → อ่านดัชนีเว็บเดิม → ตรวจแถวฐานเพลงและไฟล์ต้นทาง → ตรวจโฟลเดอร์เสียง/เนื้อร้อง → เริ่มซิงค์
3. รายงานจำนวน **แถวฐานเพลง** ที่ตรวจทุก 250 แถวในขั้นเตรียมเพลง แยกออกจากจำนวนเพลงที่แปลงหรืออัปโหลดสำเร็จ (ไม่สร้างเปอร์เซ็นต์ปลอม)
4. เมื่องานส่งข้อความสถานะใหม่จริง จะปรับเวลา 'ความคืบหน้าล่าสุด'; ตัวจับเวลาของ UI ที่หมุนเฉย ๆ จะไม่ทำให้ข้อความเตือนหยุดนิ่งหายไป
5. ถ้าไม่มีสถานะใหม่เกิน 30 วินาที จะแจ้งว่ารอ Google Drive/ดิสก์ หรือเครือข่าย และให้เลือกหยุดได้
6. แสดงรุ่น **[Recovery r4]** บนหัวหน้าต่างและข้อความใต้ชื่อ X-Stage เพื่อแยกจาก EXE เดิม
7. คง SQLite Resume Journal, การตรวจไฟล์ Drive ก่อนข้ามงาน, ข้อมูลเพลงต้นทางและฐานเพลงเดิมทั้งหมด โดยไม่ลบไฟล์หรือเปลี่ยน OAuth JSON

## ติดตั้งอย่างปลอดภัย

- บนหน้าต่างปัจจุบันที่ขึ้น "Recovery r2" หากขั้นตอน 4 ยังทำงานอยู่ ไม่จำเป็นต้องปิดเพราะครบ 73 วินาที ให้อ่านสถานะและตรวจว่าอินเทอร์เน็ตยังใช้งานได้
- หากไม่มีความคืบหน้าหลายนาที ให้กดปุ่ม **หยุด** ในโปรแกรมก่อน ไม่แนะนำบังคับ End Task หรือปิดไฟ
- สำรอง `D:\newKaraoke\Data` และเก็บโปรแกรมเก่าไว้
- แตก ZIP R4 ลงโฟลเดอร์ใหม่ **ไม่แตกทับโปรแกรมที่ติดตั้งอยู่**
- รัน `Verify-Windows-0948.cmd` และ `Build-Windows.cmd` ตามคู่มือเดิม; ติดตั้ง EXE รุ่น R4 เมื่อ Windows Build Gate ผ่านเท่านั้น
- ตรวจหัวหน้าต่างให้เห็น `[Recovery r4]` ก่อนทดสอบซิงค์ใหม่
- ในรุ่น R4 ที่ใช้บัญชี Google และ DPAPI เดิม ควรแสดงการเชื่อมต่อบัญชีที่จดจำไว้ หาก Google เพิกถอนสิทธิ์จึงต้องล็อกอินใหม่
- เลือก **ซิงค์ต่อจากครั้งก่อน** หรือกดซิงค์ใหม่ ระบบจะใช้ข้อมูลเพลงที่ตรวจสอบได้และตรวจสอบไฟล์บน Drive ก่อนนำรายการเดิมกลับมาใช้

## ผลตรวจสอบซอร์ส

- การทดสอบเฉพาะทาง (ไม่มี Google จริง): 60 รายการ ผ่านทั้งหมด (skipped 9)
- การทดสอบ GUI จำลองใน Linux/Xvfb: 11 รายการ ผ่านทั้งหมด แต่ Tk อาจพิมพ์คำเตือน after/progressbar เมื่อทำลายหน้าต่างทดสอบ
- **ยังไม่ได้ทดสอบ EXE บน Windows, Google Drive API จริง หรือการซิงค์คลังเพลง 70,000+ รายการ** จึงยังไม่รับรองผลบนเครื่องจริง
- ไม่มีไฟล์เพลงส่วนตัว, OAuth Client JSON จริง, access/refresh token หรือ DPAPI profile ใน ZIP นี้

## ข้อควรระวังด้านสถานะ

รุ่น R4 แก้การสื่อสารความคืบหน้าช่วงเตรียมซิงค์และลดรายการ Drive ที่ต้องดึง แต่ไม่ได้ทำให้ Google Drive หรือการแปลง M4A เร็วขึ้นโดยอัตโนมัติ และไม่สามารถรับรองว่าเครือข่าย/ไฟล์ต้นทางจะตอบสนองเสมอได้ หากเกิด HTTP/เน็ตล่ม ระบบควรแสดงข้อผิดพลาดให้ซิงค์ต่อได้ในภายหลัง
