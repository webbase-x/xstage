# X-Stage Karaoke Online — Fast Sync + Verify & Repair R15

ซอร์สรุ่นนี้พัฒนาต่อจาก R14 ในโครงการ Windows เดิม ไม่เปลี่ยนคลังเพลงหรือ Google Drive โฟลเดอร์ของเจ้าของบัญชี

## ทำงานที่เร็วขึ้นอย่างไร

- ซิงค์ที่เปิดใหม่ใช้รายการเพลงจากฐานเดิม (SQLite) และเช็กเนื้อหาต้นทางจริง; ไม่เดาว่าไฟล์ดีจากชื่อเพลงเท่านั้น
- **คลังเดิมบน Google Drive:** ดึงรายการและ MD5 เป็นชุดตามโฟลเดอร์เสียง/เนื้อร้องเพียงครั้งต่อโฟลเดอร์ต่อรอบ แทนการถาม API แยกทีละไฟล์และตรวจซ้ำใน prefetch ช่วยลดคำขอ API อย่างมากในคลังใหญ่ โดยยังตรวจ File ID และ MD5 จริง
- เริ่มแปลงเพลงถัดไประหว่างอัปโหลดชุดปัจจุบันด้วย worker แบบจำกัดจำนวนเพื่อไม่ใช้ RAM เกินจำเป็น
- หลังเผยแพร่เพลงชุดแรกที่ผ่านการตรวจ 10 เพลง เว็บไซต์อ่านได้ทันที ชุดต่อไปใช้ฐานส่วนเพิ่ม ทุก 200 เพลงหรือเมื่อครบประมาณ 90 วินาที แล้วรวมฐานฉบับสมบูรณ์เมื่อจบ
- บันทึกผลสำเร็จของแต่ละเพลงใน SQLite verified-upload journal **หลังตรวจ M4A + Lyrics JSON บน Drive ทั้งคู่**; ถ้าหยุด/ปิด/ไฟดับ โปรแกรมเปิดใหม่แล้วตรวจและใช้รายการเดิมที่สมบูรณ์ได้
- ลดความถี่การเขียนสถานะข้อความ UI ที่ไม่ใช่ข้อมูลอัปโหลดจริง เพื่อลด fsync ที่ไม่จำเป็น

## ตรวจความครบและซ่อมแซมอัตโนมัติ

เมื่อซิงค์/เผยแพร่สำเร็จ จะตรวจฐานเพลงที่เผยแพร่จริงทุกแถว โดยเช็ก `audio.fileId`, `lyrics.fileId` และ MD5 ของไฟล์ทั้งสองผ่าน Google Drive metadata ที่ค้นเป็นชุด ไม่ใช่เช็กเพียงว่ามีชื่อไฟล์

- เมื่อพบรายการไม่ครบและมีต้นฉบับของเพลงนั้นในเครื่องและการตั้งค่าที่ตรงกัน จะ **แปลง/นำไฟล์แคชกลับมาใช้ อัปโหลดเฉพาะส่วนที่ขาด และเผยแพร่ฐานที่ซ่อมแล้ว** จากนั้นตรวจซ้ำทั้งฐาน
- ถ้าเพลงอยู่จากเครื่องอื่น ต้นฉบับหาย หรือ Google Drive มีข้อผิดพลาดที่ซ่อมไม่ได้ จะ **แจ้งจำนวนที่ยังผิดพลาด** และไม่อ้างว่าครบ 100% รวมทั้งไม่แสดงปุ่มสำเร็จเพื่อเปิดเว็บเป็นงานที่สมบูรณ์
- รายงานความครบถูกเขียนแบบ atomic ที่ `Data/WebAssets/integrity-report.json`; ไม่บันทึกโทเค็นหรือรหัสผ่าน
- `100%` หมายถึง **ตรวจรายการที่เผยแพร่ครบทุกแถวและทุกคู่ไฟล์ผ่าน MD5** ไม่ได้หมายความว่ารับประกันเสียงหรือเวลาของเนื้อร้องถูกต้องเชิงดนตรีทุกเพลง

## พฤติกรรมเมื่อเสร็จ

เมื่อซิงค์และการตรวจครบไม่มีรายการผิดพลาด **หน้าต่าง 3/3 ยังเปิดค้างอยู่และไม่เปิดเว็บอัตโนมัติ** โดยจะแสดงสรุปจำนวนเพลงที่ตรวจ/ซ่อม ผู้ใช้ต้องกดปุ่ม **“สำเร็จ • เปิดเว็บไซต์”** จึงเปิด `https://webbase-x.github.io/xstage/` และปิดหน้าต่าง

ถ้ากดปิดโดยไม่กดสำเร็จ จะไม่เปิดเว็บ แต่ข้อมูลที่ซิงค์/เผยแพร่แล้วยังอยู่ตามเดิม

## วิธีทดสอบบน Windows

1. สำรอง `D:\newKaraoke\Data` (โดยเฉพาะ `songs.sqlite3`, `WebAssets`, ไฟล์ตั้งค่า) และอย่าลบไฟล์เพลง/ข้อมูลเดิม
2. แตกซอร์สเต็ม R15 ลงโฟลเดอร์ใหม่ หรือใช้ Hotfix R15 กับซอร์สเต็ม R14 เท่านั้น
3. รัน `Verify-Windows-0948.cmd` และ `Build-Windows.cmd` ต้องผ่านทุกการทดสอบ Windows ก่อนใช้ EXE ใหม่
4. เปิด X-Stage Karaoke → คลิกขวา → X-Stage Karaoke Online → เข้าสู่ระบบ → ยืนยันตัวเลือก → เริ่มซิงค์
5. ตรวจว่ามีรายงาน `integrity-report.json`, แถบสถานะเดิน, ปุ่มสำเร็จปรากฏเฉพาะเมื่อไฟล์ครบ และเว็บไซต์เปิดเมื่อกดปุ่มเท่านั้น
6. ทดสอบหยุด/ปิดหลังเผยแพร่ชุดหนึ่ง แล้วเปิดใหม่ ต้องใช้ไฟล์ที่ตรวจผ่านแล้วโดยไม่อัปโหลดซ้ำ

## ผลทดสอบและข้อจำกัด

- ชุดทดสอบซิงค์/กู้คืน/ตรวจไฟล์ 63 รายการ (ข้าม 3 ตามเงื่อนไข) ผ่านในสภาพแวดล้อม Linux
- GUI 17 รายการผ่านบน Xvfb; มีคำเตือนการปิด Tk callback ในบางกรณีของจอจำลอง แต่ไม่มี Failure/Error ในชุดดังกล่าว
- ทดสอบซ่อมกรณีไฟล์เสียงหาย, Lyrics หาย, เพลงบนบัญชี/เครื่องอื่นซ่อมไม่ได้, ยกเลิกกลางการตรวจ, คลังเดิมตรวจแบบเป็นชุด และยืนยันว่าไม่มีไฟล์เสียถูกระบุว่าครบ
- การรันทดสอบเต็มบน Linux จบไม่สมบูรณ์ เพราะการจำลองจอถูกตัดและบางชุดต้องใช้ PowerShell Windows; **ยังไม่ได้ยืนยัน Windows Build Gate หรือ Google Drive จริง**

**สำคัญ**: อย่ารันซิงค์บัญชี Google Drive เดียวกันจากหลายเครื่องพร้อมกัน เนื่องจาก `current.json` ยังไม่ใช่ธุรกรรม compare-and-swap ระหว่างเครื่อง
