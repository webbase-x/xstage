# X-Stage Karaoke Online — R11 แก้หน้า 2 ค้าง (Fast SQLite Preflight)

**สาเหตุจากภาพ Recovery R10:** หลัง Google Login สำเร็จ หน้า 2 เรียก `local_candidates()` ซึ่งตรวจไฟล์เพลง MID/LYR/CUR จริงและตรวจความปลอดภัยของเส้นทางทีละเพลงกว่า 70,000 เพลง **ก่อน** เปิดปุ่ม “ตกลง” และเมื่อเริ่มซิงค์ Worker ก็ตรวจไฟล์ดังกล่าวซ้ำอีกครั้ง หากเพลงอยู่บนดิสก์ช้าหรือไดรฟ์ภายนอก การตรวจจึงอาจใช้เวลานาน หน้า 2 ยังไม่แสดง progress ของการสแกนเต็มให้ผู้ใช้เห็น

## สิ่งที่แก้

1. หน้า 2 เปลี่ยนเป็น **นับรายการเพลงเบื้องต้นด้วย SQL SELECT ... GROUP BY** บน `songs.sqlite3` ใน Thread เบื้องหลัง แทนการอ่านไฟล์เพลงจริงทีละรายการ ไม่แตะ M4A, MID, LYR, CUR และไม่ติดต่อ Google Drive ระหว่างนับ
2. นับเฉพาะรายการที่ยังมองเห็น/`playable=1` และไฟล์ MID/KAR หรือฟอร์แมต NCN โดยแยก NCN/MIDI จำนวนนี้เป็น *จำนวนโดยประมาณ* — ยังไม่รับประกันว่าไฟล์บนดิสก์พร้อมใช้งานทุกเพลง
3. เมื่อมีจำนวนเพลงและ Google Session พร้อม หน้า 2 จะเปิดปุ่ม **ตกลง / ซิงค์ต่อจากครั้งก่อน** โดยไม่รอการตรวจไฟล์ทั้งหมด
4. หลังผู้ใช้กดตกลง หน้า 3 จะตรวจไฟล์เพลงจริงเพียงครั้งเดียวใน `sync_web_assets()` พร้อมรายงานความคืบหน้า **แถวที่ตรวจ/แถวทั้งหมด** ไม่ใช้เปอร์เซ็นต์จากจำนวนเพลงที่ยังไม่ผ่านการตรวจ
5. ยังคงการตรวจ `MID/LYR/CUR`, symlink/junction, fingerprint, checksum, Drive File ID, verified journal, delta catalog ก่อนเผยแพร่ฐานเว็บ ไม่มีเพลงไม่สมบูรณ์ถูกประกาศว่าเล่นได้
6. Google Login และโปรไฟล์ยังอยู่เฉพาะเมนู Online ตามรูปแบบ 3 หน้า และหน้าต่างสามารถปิด/เปิดใหม่ได้
7. เมื่อปิดก่อนเริ่มซิงค์ ไม่มีการอัปโหลดใดๆ; เมื่อหยุดระหว่างทำงาน VerifiedUploadJournal และ current.json เดิมยังคงอยู่ ซิงค์ต่อโดยตรวจไฟล์ที่อัปโหลดครบก่อนข้าม

## ความแตกต่างที่ควรสังเกต

- Recovery R10: หน้า 2 แสดง “กำลังตรวจฐานเพลงในเครื่อง” นานมาก จนปุ่มยืนยันยัง disabled
- **Recovery R11:** หน้า 2 แสดง “ข้อมูลเบื้องต้น” และปุ่มยืนยันหลัง SQL ตอบกลับ หน้า 3 จึงเริ่มตรวจ MID/LYR/CUR พร้อมสถานะจริง
- หากเพลงบางไฟล์หาย/เสีย จำนวนเพลงที่แปลงได้จริงอาจต่ำกว่าตัวเลขเบื้องต้น นี่เป็นผลจากการตรวจไฟล์ที่ถูกต้อง ไม่ใช่ DB ผิด

## วิธีนำไปทดสอบ Windows

1. หน้า R10 ปัจจุบันยังไม่ได้เริ่มซิงค์ (อยู่หน้า 2) สามารถปิดหน้าต่างได้; ถ้ากำลังอัปโหลดให้กดหยุดและรอจนจบก่อน
2. สำรอง `D:\newKaraoke\Data` โดยเฉพาะ `songs.sqlite3`, `WebAssets/`, `google-oauth-client.json` และ session ที่เข้ารหัส (ไม่ส่งข้อมูลเหล่านี้ขึ้น GitHub)
3. แตก **Windows Source — Recovery R11** ลงโฟลเดอร์ใหม่ที่ไม่ใช่โฟลเดอร์โปรแกรมติดตั้งจริง
4. รัน `Verify-Windows-0948.cmd` แล้ว `Build-Windows.cmd` ตาม Build Gate; ใช้ EXE ใหม่เมื่อผ่านจริงเท่านั้น
5. เปิดเมนูคลิกขวา → X-Stage Karaoke Online → Google Login → หน้าตั้งค่า ตรวจว่ามีปุ่มยืนยันเร็วขึ้น → กดตกลง → หน้า 3 เห็นสแกนแถวฐานเพลง/การแปลง/อัปโหลด → กดหยุด/ปิดและเปิดใหม่ทดสอบซิงค์ต่อ
6. กรณีหน้า 3 ค้างระหว่างอ่านไฟล์จริง รอดูตัวนับแถวและตรวจ Drive/ดิสก์; ไม่ต้องเคลียร์ Data หรือเริ่มซิงค์ใหม่จากศูนย์

**ขอบเขตการทดสอบ:** ชุดทดสอบของ Linux/Xvfb ไม่สามารถรับรองความเร็วของฮาร์ดดิสก์ Windows จริง, FFmpeg, Windows EXE หรือ Google Drive ที่เชื่อมต่อจริงได้ จึงต้องทดสอบบน Windows ก่อนติดตั้งแทนตัวเดิม
