# X-Stage Karaoke Online — Google Login ในหน้าต่างแรก + ซิงค์ต่อหลังดับ/ปิด/หยุด

ชุดแก้ไขสำหรับ **ซอร์ส Windows v0.9.48** (Recovery r2) ไม่ใช่ EXE สำเร็จรูป

## จุดที่เปลี่ยน

- ชื่อหน้าต่างใหม่: **`X-Stage Karaoke Online — Google Login / ซิงค์ต่อได้ [Recovery r2]`** ถ้าเปิดโปรแกรมแล้วยังไม่มีข้อความ `Recovery r2` ในชื่อหน้าต่าง แสดงว่ายังใช้ EXE เก่าอยู่ ต้อง Build และติดตั้งรุ่นใหม่
- แถวแรกของหน้าต่างมี **`G เข้าสู่ระบบ Google Drive`** สีเด่น, `เลือก OAuth JSON เดิม…`, `ยกเลิกการจดจำบัญชี` และข้อความสถานะบัญชี ก่อนแสดงตัวเลขการตรวจเพลง
- เลือก OAuth Desktop JSON จากรุ่นเดิมได้ โดยไฟล์ตัวจริงของผู้ใช้ **ไม่รวมอยู่ใน ZIP นี้**; เก็บ Refresh Token ผ่าน Windows DPAPI ตามระบบรุ่นก่อน
- บันทึกงานซิงค์ไว้ใน `Data/WebAssets/online-sync-recovery.json` แบบเขียนชั่วคราวแล้วแทนที่ (atomic replace + fsync) โดยเก็บเฉพาะขั้นตอน, ตัวนับ, ประเภทเพลง, SoundFont ที่เลือก และข้อความสถานะ **ไม่เก็บรหัสผ่านหรือ Google Token**
- เมื่อเปิดเมนูซิงค์อีกครั้ง ถ้าพบงานผิดพลาด ถูกหยุด หรือปิดไปขณะทำงาน จะแจ้งสถานะเดิม และเสนอปุ่ม **`ซิงก์ต่อจากครั้งก่อน`** หลังตรวจรายการเพลงในเครื่องอีกครั้ง ผู้ใช้ต้องกดเองก่อนเริ่มอัปโหลด ไม่มีการซิงค์อัตโนมัติโดยไม่ขอ
- บันทึกผลทีละเพลงลง **SQLite Journal** แทนการเขียน JSON ทั้งก้อนซ้ำทุกเพลง เหมาะกับคลังขนาดหลายหมื่นเพลง
- ไฟล์ที่อัปโหลดทั้ง M4A และ Lyrics JSON ครบแล้วจะมีรายการพร้อมข้อมูล Checksum ใน Journal SQLite `Data/WebAssets/sync/*.sqlite3`; เมื่อซิงค์ต่อ โปรแกรมตรวจไฟล์จริงบน Drive อีกครั้ง ถ้าตรงจะ **ข้ามทั้งการแปลงและการอัปโหลด** เพลงนั้น ถ้าไม่ตรงจะกลับไปทำใหม่
- ไฟล์ที่กำลังแปลงหรือยังอัปโหลดไม่ครบตอนเครื่องดับต้องทำเพลงนั้นใหม่ แต่ไฟล์ต้นฉบับในเครื่องและ Catalog บน Drive รุ่นที่เผยแพร่อยู่ **ไม่ถูกลบ**
- ไฟล์เพลงหลักเก็บใน `Data/songs.sqlite3` และคิวใน `Data/queue.json` ซึ่งคงอยู่หลังปิดโปรแกรมอยู่แล้ว การตรวจสอบความเปลี่ยนแปลงของรายการเพลงหลังเปิดใหม่จะสแกนอีกครั้งเพื่อความถูกต้อง ไม่อาศัยจำนวนครั้งก่อนโดยไม่ตรวจสอบ

## วิธีนำไปใช้จริงกับเครื่อง Windows

1. สำรอง `D:\newKaraoke\Data` รวมถึง `songs.sqlite3`, `queue.json`, ไฟล์ OAuth และไฟล์ `.dpapi` ก่อนทุกครั้ง
2. แตก ZIP ซอร์สนี้ลง **โฟลเดอร์ใหม่** (ไม่ทำทับของเดิม)
3. เปิด `ตรวจรุ่นซิงค์ออนไลน์.cmd` เพื่อยืนยันว่าซอร์สชุดนี้มี Google Login และระบบกู้คืน
4. รัน `Verify-Windows-0948.cmd` ให้ Test Gate ผ่านก่อน แล้วจึง `Build-Windows.cmd` เพื่อสร้าง `dist\XStageKaraoke\XStageKaraoke.exe` รุ่นใหม่
5. ตรวจ EXE ใหม่ก่อนติดตั้งทับ: เข้าเมนู **X-Stage Karaoke Online** ต้องเห็น `[Recovery r2]` และปุ่ม **G เข้าสู่ระบบ Google Drive** บนแถวแรก ถ้ายังเห็นหน้าต่างแบบเก่า ให้ตรวจว่ากำลังเปิด EXE ตัวใดอยู่
6. เชื่อมบัญชี/เลือก Desktop OAuth JSON เดิมตามที่จำเป็น เลือกชนิดเพลงและ SoundFont แล้วกดซิงค์ ถ้ามีงานค้างจะพบปุ่มซิงค์ต่อ
7. ทดสอบการหยุดงานด้วยปุ่ม **หยุด** ก่อน แล้วเปิดใหม่และซิงค์ต่อ หลีกเลี่ยงการดึงปลั๊กจริงเพื่อทดสอบ

## ข้อจำกัดที่ต้องทราบ

- ซอร์สนี้ยังไม่ได้ Build เป็น Windows EXE หรือยืนยัน Google Login จริงด้วยบัญชีของคุณในสภาพแวดล้อมนี้
- **ไฟล์ต้นทางที่เสียหาย, disk/SQLite เสียหาย หรือ Google เพิกถอน Refresh Token** ไม่สามารถกู้คืนโดยไม่มีข้อมูล/สิทธิ์ที่ถูกต้องได้ ควรมีสำรองออฟไลน์
- `current.json` บน Google Drive จะถูกชี้ไปรุ่นใหม่เมื่ออัปโหลดและตรวจครบตามตรรกะของโปรแกรมเท่านั้น ระหว่างการซิงค์ควรใช้พีซีเดียว ไม่ซิงค์จากสองเครื่องพร้อมกัน
- โปรแกรมไม่สามารถดึงการแปลงเพลงที่กำลังทำอยู่กลางไฟล์กลับมาต่อจากเฟรมเดิมได้ แต่ไม่ต้องทำซ้ำเพลงที่อัปโหลดและตรวจสอบครบแล้ว
- ระบบจดจำบัญชี Windows ใช้ได้เมื่อ Google ยังให้ Refresh Token ใช้งานได้เท่านั้น ห้ามนำข้อมูล OAuth ส่วนตัวไปเผยแพร่บน GitHub
