# X-Stage Karaoke Online — Responsive Wizard & Clean Idle R12

## สิ่งที่แก้ไขจริงในซอร์ส

- Google Login อยู่เฉพาะหน้าต่าง X-Stage Karaoke Online ที่เปิดจากเมนูคลิกขวา หน้า 1 แสดงปุ่มเข้าสู่ระบบและการกู้เซสชันเดิม เจ้าของบัญชีต้องกดปุ่มดำเนินการต่อ
- หน้า 2 แสดงรูปโปรไฟล์ Google (ถ้าอ่านได้), ชื่อและอีเมล และตัวเลือก SoundFont/NCN/MIDI โดยมีปุ่มตกลงซิงค์หรือซิงค์ต่อจากครั้งก่อน ข้อมูล SoundFont/เพลงไม่ได้บังคับตรวจไฟล์ทั้งหมดก่อนเปิดปุ่ม
- หน้า 3 แสดงรูปโปรไฟล์/ชื่อ/อีเมลซ้ำ พร้อมแถบแปลงเพลง อัปโหลด Drive และเผยแพร่ฐานเว็บ แยกเปอร์เซ็นต์จริง: ต่ำกว่า 25% สีแดงส้ม, 25–49% สีเหลือง, 50–74% สีฟ้า, 75–100% สีเขียว ระหว่างยังไม่มีตัวหารแสดงว่ากำลังตรวจสอบแทนการเดาเปอร์เซ็นต์
- หน้า 3 มีปุ่มหยุดและบันทึกงานค้าง ระบบใช้ SQLite Recovery/Journal เดิม ข้อมูลที่เผยแพร่ครบแล้วยังใช้งานได้ เปิดซ้ำให้ยืนยันการซิงค์ต่อ ไม่เริ่มอัปโหลดอัตโนมัติ
- หน้า Online ทุกขั้นตอนใช้พื้นที่แสดงผลเดียวกัน มีตัวเลื่อนแนวตั้งและปุ่มจัดวางตามหน้าต่างที่แคบลง ลดข้อความที่ไม่สำคัญ
- ปรับขนาดหน้าต่าง PC ให้ไม่บังคับเรขาคณิตเริ่มต้นหรือขนาดขั้นต่ำใหญ่กว่าขนาดจอ
- PC: เส้นทางตรวจว่าเพลงจบเรียก completion handler ตามจริง และเมื่อคิวว่างคืน engine, ล้างข้อมูลเพลงและ Lyrics แล้ววาดเวทีสถานะว่างแทนข้อความเพลงเดิม
- เว็บใน repository เดิม `webbase-x/xstage`: เมื่อเพลงจบโดยไม่มีคิว ยกเลิก audio source, blob URL และ Lyrics, ล้าง canvas และคืนเวทีสถานะว่าง เพลงในคิวเล่นต่อได้ตามปกติ; ปรับ CSS สำหรับจอแคบ/แนวนอนเตี้ย
- เว็บมีรุ่น cache-buster `?v=0968` เพื่อหลีกเลี่ยง CSS/JS ค้าง

## การใช้งาน Windows

1. สำรอง `D:\newKaraoke\Data` ก่อนทุกครั้ง (รวม `WebAssets` และไฟล์ฐานเพลง)
2. หยุดการซิงค์ที่กำลังทำงานอยู่ แล้วแตก ZIP ซอร์สเต็ม R12 ในโฟลเดอร์ใหม่ **ห้ามแตกทับโปรแกรมที่กำลังทำงาน**
3. รัน `Verify-Windows-0948.cmd` ให้ผ่านก่อน และรัน `Build-Windows.cmd` เพื่อสร้าง EXE
4. เปิด EXE ใหม่ และเปิดเมนูคลิกขวา > X-Stage Karaoke Online > Login > ตรวจบัญชีและตัวเลือก > ตกลง > ดูสถานะ
5. หากงานช้า ใช้ปุ่มหยุดและบันทึกงานค้าง แล้วเปิดอีกครั้งเพื่อกดซิงค์ต่อจากครั้งก่อน
6. เมื่อซิงค์ครบโดยไม่ผิดพลาด โปรแกรมจะเปิดเว็บไซต์แล้วปิดหน้าต่างเอง เพลงที่เผยแพร่เป็นชุดก่อนหน้ายังอยู่บน Drive ส่วนตัวตามเดิม

## การทดสอบและข้อจำกัด

- Python compileall ผ่าน
- ทดสอบ GUI และ regression เฉพาะส่วน Online/การกลับมาทำต่อ/บัญชี/คิว/การจบเพลง 77 รายการผ่าน (รันแบบ GUI จำลอง มีคำเตือน Tk บางกรณีจากการทำลายหน้าต่างตรง ๆ ใน test teardown)
- ทดสอบเสียง/เมดเลย์/ฐานและ Pipeline เพิ่มเติม 54 รายการ (ผ่าน 53 ข้าม 1)
- เว็บ: ตรวจ JavaScript syntax ผ่าน และจำลองการจบเพลงแบบไม่มีคิว ยืนยันว่า Audio, Blob URL, Lyrics, Canvas และสถานะเวทีถูกล้าง
- **ยังไม่ได้รัน Windows Build Gate ทั้งหมด, Windows PowerShell เฉพาะเครื่อง, Google Drive จริง หรือทดสอบฮาร์ดแวร์ทุกความละเอียด**; ไม่ควรอ้างว่าไม่มีข้อผิดพลาดหรือยืนยันประสิทธิภาพกับ 70,000 เพลงบนเครื่องจริง
- การทดสอบรวมทั้งโครงการแบบครั้งเดียวบน Linux มีบางกรณีรันเกินเวลาที่กำหนด จึงรายงานเฉพาะชุดทดสอบที่จบจริง

## ข้อควรระวัง

- Google OAuth JSON/token/DPAPI ต้องอยู่เฉพาะใน `Data` ของเครื่อง ไม่รวมใน ZIP หรือ GitHub
- เก็บไฟล์เพลงและฐานข้อมูลส่วนตัวไว้บน Google Drive ที่เจ้าของบัญชีเข้าถึงได้ ไม่เผยแพร่ไฟล์เพลงใน GitHub Pages
- ระบบเมดเลย์ที่เปิดโดยเจตนามีการทำงานเฉพาะของมัน; การจบเพลงทั่วไปเมื่อไม่มีคิวจะแสดงเวทีว่างเสมอ
