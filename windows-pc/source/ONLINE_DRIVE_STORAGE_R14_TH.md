# X-Stage Karaoke Windows — Google Drive Storage R14

## สิ่งที่เพิ่มในหน้าต่าง Online หน้า 3/3

1. **ใช้จริง (Google ทั้งบัญชี)** — ดึง `storageQuota.usage` และ `storageQuota.limit` จาก Drive API v3 `about.get` (`fields=storageQuota(limit,usage,usageInDrive,usageInDriveTrash)`) ด้วย OAuth `drive.file` เดิม ไม่เพิ่มสิทธิ์ ไม่เปลี่ยนการล็อกอิน ตรวจข้อมูลแบบ asynchronous ประมาณทุก **30 วินาที** ตราบเท่าที่เปิดหน้า 3/3 อยู่ การเชื่อมต่อช้าจะไม่หยุดหน้าต่างหรือ Pipeline อัปโหลด ข้อมูล Drive ในวงเล็บเป็น `usageInDrive`; พื้นที่ที่นำมาหารด้วยโควตาคือ `usage` **ทุกบริการ** ไม่ใช่ `usageInDrive` เพียงอย่างเดียว (Gmail / Photos ฯลฯ อาจนับรวม)
2. **คาดการณ์เมื่อซิงค์ครบ** — ประมาณจากไฟล์ **M4A และ Lyrics JSON ที่อัปโหลดสำเร็จและตรวจ MD5 แล้วจริง** ในช่วงเพลงล่าสุดสูงสุด 120 เพลง (รวมเพลงที่ยืนยันว่าไฟล์บน Drive มีครบแล้ว ซึ่งนับเพิ่ม 0 ไบต์) แล้วคูณค่าเฉลี่ยไบต์ใหม่ต่อเพลงด้วยจำนวนเพลงที่ยังไม่ได้ประมวลผล; บวกกับยอดใช้จริงที่ Google รายงานล่าสุด **ไม่ได้** นับ MIDI ต้นทางเป็นขนาด M4A ในอนาคต แสดงคาดการณ์ได้เมื่อมีอย่างน้อย 12 เพลงที่ตรวจ และอย่างน้อย 3 เพลงที่มีไฟล์อัปโหลดใหม่ หากยังไม่พอ แสดงสถานะรอตัวอย่าง แทนการแสดง 0% หลอก

สูตรโดยสรุป:

`การใช้เมื่อเสร็จโดยประมาณ = การใช้จริงล่าสุด + (เพลงที่ยังไม่ประมวลผล × ไบต์ใหม่เฉลี่ยต่อเพลงในชุดตัวอย่าง)`

เมื่อทราบ `limit`:

`% ใช้จริง = usage / limit × 100`

`% คาดการณ์ = projected_usage / limit × 100`

หาก Google ไม่ส่ง `limit` (บัญชีไม่จำกัด/Google Workspace) แสดงขนาดพื้นที่เป็นหน่วยไบต์แทนเปอร์เซ็นต์ และไม่ประดิษฐ์เพดานความจุ

สีแถบ **ความจุบัญชี**: ต่ำกว่า 50% เขียว, 50–74.9% ฟ้า, 75–89.9% เหลือง, 90% ขึ้นไป ส้มแดง (พื้นที่ใกล้เต็มเป็นคำเตือน) ส่วนสีแถบ **ความคืบหน้าของงาน** ใช้รูปแบบเดิม 0–24% สีส้มแดง, 25–49% เหลือง, 50–74% ฟ้า, 75–100% เขียว

## ข้อจำกัดที่ต้องเข้าใจ

- **ไม่ใช่การคาดการณ์ที่รับประกัน** ขนาด M4A ขึ้นกับระยะเวลาเพลง เสียง SoundFont และไฟล์ต้นฉบับ เพลงถัดไปอาจไม่เหมือนตัวอย่าง; ระบบรายงานชัดว่าเป็นค่าประมาณ
- การใช้พื้นที่ที่ Google รายงานอาจอัปเดตช้ากว่าการอัปโหลดจริง และ Google อื่น ๆ อาจใช้พื้นที่พร้อมกัน ตัวเลขจึงอาจเปลี่ยนระหว่างซิงค์
- การทับไฟล์เดิม/การจัดเก็บเวอร์ชันไฟล์มีผลต่อการคิดพื้นที่จริง การประเมินไบต์จากไฟล์ที่เขียนใหม่อาจสูงกว่าหรือต่ำกว่าการคิดพื้นที่ของ Google
- หากเป็นบัญชีองค์กรแบบ Shared/Pooled storage ตัวเลข Google อาจเป็นระดับองค์กร ไม่ใช่ผู้ใช้รายคน
- หาก Google ไม่ตอบหรือบัญชีหมดอายุ แถบจะแสดงสถานะรอ/อ่านไม่ได้ แต่ **ซิงค์ไม่ล้มเหลวเพียงเพราะอ่านพื้นที่ไม่ได้**
- หากขนาดพื้นที่จริงเข้าใกล้เต็ม Google อาจไม่อนุญาตให้อัปโหลด ระบบซิงค์จะแสดงข้อผิดพลาดตามปกติและบันทึกงานค้างให้ทำต่อ

## สิ่งที่ไม่มีการเปลี่ยนแปลง

- ระบบ Google Login 3 หน้า, รูปโปรไฟล์, การแปลง/อัปโหลดพร้อมกัน, เพลงที่เผยแพร่แล้วบนเว็บไซต์, ระบบ Resume SQLite, OAuth DPAPI และสิทธิ์ Google Drive `drive.file` เดิม
- ไม่เผยแพร่เพลง/โทเค็น/ไฟล์ OAuth JSON บน GitHub
- ไม่ลบไฟล์เดิมบน Google Drive และไม่แก้ฐานข้อมูลเพลงเดิมจากการอ่านค่าโควตา

## ผลทดสอบ (สภาพแวดล้อม Linux/Xvfb)

- ทดสอบกลุ่มซิงค์/บัญชี/ระบบตรวจเก่าที่เกี่ยวข้อง: 108 รายการ, skipped 10, failure/error 0
- ทดสอบ GUI Xvfb ของหน้าต่าง Online/บัญชี/การย่อจอ/ความจุ: 21 รายการ ผ่าน, failure/error 0
- ทดสอบฟังก์ชันคำนวณ: ตรวจการไม่มี `limit`, การใช้ quota รวม, การนับเพลงเดิมบน Drive เป็น 0 ไบต์ใหม่, การรายงานขนาดอัปโหลดหลังตรวจสำเร็จ, การไม่สร้างเปอร์เซ็นต์หากตัวอย่างไม่พอ
- **ไม่ได้ทดสอบ Google Drive ของผู้ใช้จริงหรือ Windows EXE จริง** และการทดสอบรวมแบบรันรวดเดียวบน Linux ยังไม่จบภายในเวลาของสภาพแวดล้อมนี้ ต้องผ่าน `Verify-Windows-0948.cmd` / `Build-Windows.cmd` ใน Windows ก่อนเปลี่ยน EXE

## ติดตั้ง

1. ปิดงานซิงค์เดิมอย่างปลอดภัย สำรอง `D:\newKaraoke\Data` โดยเฉพาะ `WebAssets` และ `songs.sqlite3`
2. แตกซอร์สเต็ม R14 ในโฟลเดอร์ใหม่ (หรือแตก Hotfix R14 ทับซอร์ส R13 โดยคงโครงสร้างโฟลเดอร์)
3. รัน `Verify-Windows-0948.cmd` แล้ว `Build-Windows.cmd` เท่านั้นเมื่อ Build Gate PASS
4. เปิด EXE ใหม่ → เมนูคลิกขวา → X-Stage Karaoke Online → Login → ตั้งค่าซิงค์ → หน้า 3/3
5. หากค่า Google ไม่แสดง ให้ตรวจการเชื่อมต่อและบัญชี Google; การอ่านโควตาเป็นข้อมูลเสริม ไม่ควรลบ OAuth หรือแคชเพลง

แหล่งอ้างอิง Drive API: https://developers.google.com/workspace/drive/api/reference/rest/v3/about และ https://developers.google.com/workspace/drive/api/reference/rest/v3/about/get
