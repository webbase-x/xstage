# X-Stage Karaoke 0.9.0
วันที่ 6 พฤศจิกายน 2569 (Asia/Bangkok)

รุ่น MINOR เพิ่มระบบคุณภาพเพลงและรายงานลบถาวรตามคำขอ พร้อมแก้ audit ทั้ง 6 ข้อ

## เกณฑ์ก่อนนำเข้า
- ชื่อเพลง + นักร้อง + คีย์ต้นฉบับตรงกันถือว่าซ้ำ ปรับตัวพิมพ์ ช่องว่าง NFC และคีย์ที่เป็นเสียงเดียวกัน เช่น C# / Db; แยก C Major กับ C Minor
- ไม่ใช้ค่าปรับคีย์ในคิวแทนคีย์ต้นฉบับ อ่านคีย์จาก NCN/EMK header, MIDI key signature หรือ LRC [key:] และแก้คีย์ในหน้ารายการได้
- MIDI/KAR: โครงสร้างครบ มีโน้ตที่ส่งเสียง ระยะเวลาใช้ได้ และเนื้อร้องพร้อมเวลา (ฝังในไฟล์หรือ LRC)
- NCN: MIDI + LYR + CUR ครบ เวลาและตัวอักษรจับคู่ได้; EMK: ตรวจ archive checksum และ MIDI/LYR/CUR ภายในครบ
- เพลงเสียง: เปิดตัวถอดรหัสและระยะเวลาได้ มี LRC พร้อมเวลา; WAV ตรวจข้อมูลเฟรมครบตามส่วนหัว
- วิดีโอ: ตัวถอดรหัสเปิดได้ ระยะเวลา/ภาพใช้ได้ ไม่บังคับ LRC ภายนอกเพราะอาจฝังคำร้องในภาพ
- ทุกประเภทต้องมีชื่อ นักร้อง และคีย์ที่ระบุได้; ไม่เดาคีย์จากเสียง ข้อมูล/codec ที่ยืนยันไม่ได้แยก “ต้องตรวจเพิ่ม” ไม่ลบทิ้งรวม
- ไม่คัดลอกไฟล์ที่ไม่ผ่านการตรวจ ไม่อนุญาตเก็บทั้งสองเมื่อชื่อ นักร้อง คีย์เหมือนกัน; ใช้เดิมหรือใช้ไฟล์ใหม่แทน ID เดิมได้
- นำเข้าไฟล์เดิมจะอัปเดต metadata ก่อนตรวจซ้ำ รักษา ID/เพลงโปรด/ข้อมูลแก้เอง; รายการเดิมที่ยืนยันว่าไม่สมบูรณ์จะออกจากผลค้นหาปกติ แต่ไฟล์ยังอยู่รอตรวจรายงานและยืนยัน

## ตรวจหลังนำเข้าและลบอย่างปลอดภัย
เปิด “จัดการเพลงซ้ำ…” จากหน้าจัดการเพลงหรือเมนูคลิกขวา เพื่อเปิดระบบตรวจคุณภาพรวม
1. ตรวจคลัง ยังไม่ลบไฟล์ ออกรายงานครบ/ไม่ครบพร้อมเหตุผล แยก สมบูรณ์/ซ้ำ/ไม่สมบูรณ์/ต้องตรวจเพิ่ม/ป้องกันไว้
2. รายงานที่ยกเลิกหรือเกณฑ์เก่าใช้ลบไม่ได้ เลือกเก็บชุดสมบูรณ์ที่มองเห็นอยู่ก่อน จากนั้น ID น้อยสุด
3. ตรวจรายงาน CSV เลือกแถวหรือเลือกรายการที่ลบได้ทั้งหมด แล้วพิมพ์ “ลบ” เพื่อยืนยัน
4. ตรวจ ID/metadata/ชุดไฟล์/SHA256 อีกครั้ง รวมชุดหลัก; ระงับเมื่อไฟล์เปลี่ยน ใช้งานอยู่ อยู่ในคิว เป็นเพลงโปรด หรือมีข้อมูลแก้เอง ไฟล์ที่ใช้ร่วมกับรายการอื่นเก็บไว้
5. สำรองฐานข้อมูลและสำเนาเนื้อหาไฟล์ที่ตรวจ hash แล้วก่อนลบต้นทาง ลบเฉพาะไฟล์ตามแผนด้วย Windows handle ไม่ใช้การลบโฟลเดอร์แบบ recursive
6. นำออกจากผลค้นหาแต่รักษา ID เป็น tombstone เพื่อประวัติ/การอ้างอิง มีบันทึกงานถาวรและปุ่มกู้คืนไฟล์จากสำรอง โดยไม่เขียนทับไฟล์ที่มีอยู่
ไม่มีการลบเพลงจริงอัตโนมัติจากการติดตั้ง เปิดโปรแกรม หรือสแกน ต้องผ่านรายงานและยืนยันก่อนเสมอ

## แก้ audit
- ผูก flag เนื้อหาเหมือนกับ keeper ที่แสดงจริง แยกจากการชนชื่อ
- ตรวจชนิดรายการแหล่งเพลงและ marker ก่อน migration เพื่อเข้า recovery เมื่อค่าตั้งผิด
- ดักข้อผิดพลาด message/tick และนัดอัปเดตต่อได้เมื่อบันทึก EQ ล้มเหลว
- อัปเดต catalog metadata ที่ไม่ได้แก้เองได้ โดยรักษาข้อมูลแก้เอง
- อัปเดตไฟล์เดิมทีละไฟล์ได้ แม้แก้ metadata โดยขนาดไม่เปลี่ยน
- สร้างรายการมีเจ้าของ backup เพียงชั้นเดียว

## ข้อจำกัดที่ต้องทราบ
ตัวตรวจเปิด codec/ตรวจโครงสร้างและเวลา ไม่ใช่การฟังทุกโน้ตหรือพิสูจน์ว่าเฟรมวิดีโอทุกเฟรมดีทั้งหมด ข้อผิดพลาดที่ยังยืนยันไม่ได้ไม่ถูกเสนอให้ลบรวม
ไฟล์ที่ถูกลบจากต้นทางยังมีสำรองตรวจ hash ไว้เพื่อกู้คืน ต้องดูแลพื้นที่สำรองด้วยตนเอง ไม่มีการล้างสำรองอัตโนมัติ
ฐานข้อมูลกับไฟล์หลายไฟล์ไม่ได้ commit พร้อมกันแบบ atomic เมื่อไฟดับ/ถูก kill ให้ใช้บันทึกงานและกู้คืนจากสำรองก่อนทำซ้ำ ไม่รันแผนเก่าซ้ำทับโดยไม่ตรวจ
ตรวจคลังใหญ่ใช้เวลาตามจำนวน/ขนาดไฟล์และดิสก์ ทำบน worker จำนวนจำกัด ลด priority และมีความคืบหน้า ไม่อ้างว่าตรวจครบจนกว่า summary.complete=true
