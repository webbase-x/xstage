# X-Stage Karaoke — เลือกโฟลเดอร์ Google Drive และสร้าง SQLite ภายหลัง

## สร้างฐานใหม่ได้ทั้ง Karaoke PC และ Karaoke Online

ใช้ฐานข้อมูลร่วมกันเพียงไฟล์เดียว: \`XStageKaraoke/DB/songs.sqlite3\`.
\`Song Studio Pro\` เก็บฐานตัดต่อของตัวเองแยก ไม่เขียนฐานคาราโอเกะร่วม

**จาก Karaoke PC (Windows + Google Drive for desktop)**:
เปิด **เพลง → สร้างฐานใหม่สำหรับ PC / Online…** เลือกโฟลเดอร์
\`XStageKaraoke\`, กด **ตรวจไฟล์และ MIDI ซ้ำ** แล้ว **สร้างฐานใหม่สำหรับ PC / Online**.
ตัวสร้างตรวจ SHA-256 ภายใน XMID, XSK2/MIDI/metadata และ MD5 แพ็กเกจ,
ตรวจ MIDI ซ้ำ, สร้างสคีมา \`shared-v1\` พร้อม ID เลข 53 บิตที่อ้าง
\`web_song_id\`, พาธ \`SONGS/...\` และข้อมูลสำหรับ Web. ก่อนแทนที่
จะตรวจฐานเก่าอีกครั้ง สำรอง \`BACKUP\` และเปลี่ยนไฟล์ในเครื่องแบบ atomic
โดยไม่มีการลบเพลงต้นฉบับ

ข้อจำกัดที่หลีกเลี่ยงไม่ได้: Google Drive for desktop **ไม่เปิดเผย Google Drive
File ID ผ่านพาธไฟล์** จึงเก็บรายการที่ไม่มี File ID ด้วยสถานะ
\`pendingDriveLink\` และ MD5/ขนาด/พาธที่ตรวจแล้ว. เมื่อซิงก์ขึ้น Drive
และเปิดเล่นผ่าน Online โปรแกรมจะจับคู่ File ID ตามโครงสร้างโฟลเดอร์
\`XStageKaraoke/SONGS\` ของบัญชีที่เชื่อม ตรวจ **พาธ ขนาด MD5 และชื่อไฟล์**
ก่อนเปิดเพลง; หากค้นหาไม่ได้หรือมีชื่อซ้ำจะหยุด ไม่เดาไฟล์มาแทน.
รายการที่ยังไม่ผูก File ID ยังใช้ค้นหา/เรียกเพลงใน PC ได้ตามพาธของเครื่อง

**จาก Karaoke Online**:
เปิดจัดการคลัง > เลือก \`SONGS\` > **สร้างฐานใหม่สำหรับ PC / Online**.
Web ดึง File ID จาก Google Drive โดยตรง ตรวจ XMID/XSK และสร้าง
SQLite สคีมา \`shared-v1\` เดียวกันอย่างปลอดภัย. เมื่อ Google Drive
for desktop ซิงก์ SQLite ลง Windows, Karaoke PC จะเปิดฐานล่าสุดได้

**ขอบเขตรุ่นนี้**: ตัวสร้างฐานใหม่แบบสองทางรองรับ **XMID และ XSK2**.
ไฟล์ MP3/วิดีโอและแหล่ง NCN เดิมต้องผ่านระบบนำเข้าที่รองรับข้อมูลประกอบ
หรือขยายตัวตรวจเฉพาะรูปแบบก่อน ไม่แสดงว่าเสร็จสมบูรณ์ทั้งคลังหากยัง
ไม่ได้ตรวจ ไฟล์ซ้ำถูกรวมที่ฐานเท่านั้น ไม่ลบไฟล์จริงโดยอัตโนมัติ.
ทั้ง PC/Web ต้องไม่สร้างฐานพร้อมกัน; กลไกล็อกคลาวด์และ Google Drive
for desktop มีความหน่วงในการซิงก์ ขณะสร้างจาก PC ควรงดสร้างจาก Web
จน Google Drive for desktop ยืนยันว่าอัปโหลดเสร็จ

## ฐานเพลงร่วม PC / Online รุ่นใหม่ (สร้างใหม่จาก SONGS)

**ใช้ฐานเดียวจริง**: `XStageKaraoke/DB/songs.sqlite3` มีตาราง `songs`
ที่รวมข้อมูลของทั้ง Karaoke Online และ Karaoke PC ในระเบียนเดียวกัน
(`web_song_id`, `id` จำนวนเต็มที่คงที่, `code`, `title`, `artist`,
`source_format`, `path`, `payload`, `midi_md5`, `search`).
`path` ต้องสัมพันธ์กับ `SONGS/` ไม่ใช่พาธ `C:\\` หรือ `G:\\` ของเครื่องใดเครื่องหนึ่ง
และจะตรวจการชนของไฟล์บน Windows ก่อนเผยแพร่

**ลำดับทำงาน**:
1. บน Karaoke Online เลือกคลัง `XStageKaraoke` และเลือกแหล่งเพลง `SONGS`
   ซึ่งต้องเป็นโฟลเดอร์ลูกตรงของคลังหลัก
2. กด **สร้างฐานใหม่สำหรับ PC / Online**; ยืนยันการสร้างฐานใหม่จาก XMID/XSK,
   ตรวจ MIDI ภายในเพื่อตัดรายการซ้ำ, ตรวจข้อมูลและเผยแพร่ไฟล์เดียว.
   ช่วงนี้ยังทำดัชนีผ่าน Drive โดยตรงเฉพาะ XMID/XSK; ไฟล์เสียง/วิดีโอใช้
   ตัวนำเข้าแบบเดิมก่อน อย่าอ้างว่าเพลงเหล่านี้ถูกสร้างฐานใหม่ครบแล้ว
3. รอ Google Drive for desktop ซิงก์ `DB/songs.sqlite3` และ `SONGS` ลง PC.
4. บน Karaoke PC เปิด **เพลง → Google Drive · ใช้ DB/songs.sqlite3 ร่วมกับ Online**,
   ตรวจฐานแล้วกด **ใช้ Google Drive เป็นฐานหลักของ PC** จากนั้นเปิด PC ใหม่
5. หน้าค้นหาหลัก, คิวเพลง และตัวเล่น PC จะอ่านแถวเดียวกันจากฐาน Drive;
   ไม่สร้างรายการเพลงอีกชุดในฐาน `data/songs.sqlite3` ของ PC. รหัส
   `id` จะคงเดิมตราบใดที่ `web_song_id` ของเพลงนั้นไม่เปลี่ยน.
6. ส่งเพลงใหม่จาก PC หรือ Song Studio Pro เข้าผ่าน Google Drive for desktop;
   หลังซิงก์ให้กดตรวจและอัปเดตฐานบน Karaoke Online. ไม่ให้ PC หรือ Studio
   เขียน DB ด้วยตัวเองระหว่าง Google Drive ซิงก์

**ฐานทำงาน Song Studio Pro**: ยังคงแยกไว้สำหรับตัดต่อ/ผลิตเพลง
ส่วนไฟล์เพลงที่ส่งเข้า `SONGS` และฐานเพลงที่ Online เผยแพร่ใช้ร่วมกับ Karaoke PC.

**ปลอดภัยต่อการสร้างใหม่**: สร้าง SQLite ใหม่ในหน่วยความจำ ตรวจความถูกต้อง
และตรวจอัตลักษณ์ฐานที่อยู่บน Drive อีกครั้งก่อนแทนที่ ไม่มีการเขียนทับ
SQLite เดิมจาก PC; ยกเลิกก่อนเผยแพร่จะไม่แตะฐานปัจจุบัน และหยุดระหว่าง
ตรวจไฟล์สามารถใช้จุดบันทึกทำต่อได้ โดยคงโหมดสร้างใหม่ไว้

**ข้อจำกัดก่อนรับรอง**: ต้องทดสอบ Windows EXE, เส้นทางจริง
ของ Google Drive for desktop, การเล่น XMID/XSK ผ่านเครื่องเสียง, กรณี
Drive ยังไม่ซิงก์ไฟล์เพลง, และการเปลี่ยนฐานขณะมีผู้ใช้อีกเครื่อง;
CI เพียงอย่างเดียวไม่ยืนยันการใช้งานจริงทั้งหมด


## หลักการ
คลังหลักยังคงเป็น `XStageKaraoke` ที่กำลังเลือกในหน้า Karaoke Online และฐานเล่นเพลงเพียงไฟล์เดียวคือ `XStageKaraoke/DB/songs.sqlite3`. ห้ามใช้คลัง Google Drive เดิมที่ยกเลิกแล้ว

ในหน้าต่าง **นำเข้าเพลง / SoundFont** มีตัวเลือก Google Drive 3 ประเภทที่แยกอิสระ:
- **เพลง:** โฟลเดอร์ต้นทาง XMID/XSK ที่มีอยู่บน Google Drive (รวมโฟลเดอร์ย่อย)
- **SoundFont:** โฟลเดอร์ SF2/SF3 โดยตรงหรือมีโฟลเดอร์ย่อย SF2, SF3; ตัวเล่น MIDI ใช้ตำแหน่งนี้ทันที
- **FX:** โฟลเดอร์ FX ของเวที; เมนูเสียงเอฟเฟกต์หน้าเวทีสามารถโหลด WAV, MP3, OGG, M4A ที่เข้าถึงได้ และจำกัด 10 ไฟล์ / 48 MiB ในหน่วยความจำ

การเลือกโฟลเดอร์ใช้ Google Picker พร้อมบัญชี Google ที่ล็อกอินแล้ว เก็บเฉพาะ Folder ID และชื่อใน localStorage แยกตามรหัสบัญชีและคลังที่เลือก **ไม่เก็บ OAuth token หรือเนื้อหาไฟล์ไว้ในรายการตั้งค่า** เปลี่ยนโฟลเดอร์ได้โดยไม่ย้ายหรือลบไฟล์เดิม

## วิธีใช้งานแบบสองขั้นตอน

1. เชื่อม Google และเลือกคลัง `XStageKaraoke` ที่ยังใช้งาน
2. อัปโหลดไฟล์ XMID/XSK เข้าคลังผ่านโปรแกรม โดยเลือก **อัปโหลดไฟล์อย่างเดียว** หรืออัปโหลดเข้า Google Drive ด้วยวิธีที่ต้องการ
3. ในส่วน **เลือกแหล่งข้อมูลบน Google Drive** กดเลือกโฟลเดอร์เพลงผ่าน Google Picker
4. กด **ตรวจไฟล์บน Drive และสร้าง DB/songs.sqlite3**
5. ระบบสแกนทุกโฟลเดอร์ย่อยที่แอปอ่านได้ ตรวจ SHA-256 ภายใน XMID และ MD5 ของ MIDI ภายใน ตัด MIDI ที่มีเนื้อหาเหมือนกัน และเพิ่มเฉพาะเพลงใหม่เข้าแค็ตตาล็อกเดิม
6. เมื่อการตรวจครบและผ่าน จึงสร้าง/ตรวจ SQLite และเผยแพร่ใน `DB` ครั้งเดียว โดยกลไกเดิมสำรองฐานก่อนหน้าหากมี

ปุ่ม **ยกเลิกการสร้างฐาน** หยุดการตรวจโดยไม่มีการเผยแพร่ฐานที่ยังไม่สมบูรณ์ และไม่ลบไฟล์บน Google Drive หากไม่มีเพลงใหม่ให้เผยแพร่จะไม่เขียน DB ใหม่

## ข้อจำกัดและความปลอดภัย

- โหมด **สร้าง DB จาก Drive ภายหลัง** รองรับ **XMID/XSK** ที่ตรวจสอบได้ก่อน รูปแบบ MID/NCN, MP3 และวิดีโอสามารถนำเข้าผ่านขั้นตอนนำเข้าและสร้างฐานตามปกติได้ แต่ยังไม่ถูกทำดัชนีด้วยคำสั่งสร้าง DB ภายหลัง
- ขอบเขต OAuth ปัจจุบันคือ `drive.file`: การเลือกโฟลเดอร์ผ่าน Google Picker **ไม่รับประกัน** ว่าแอปจะอ่านไฟล์ทุกไฟล์ภายในที่อัปโหลดด้วยบัญชีหรือโปรแกรมอื่นได้ ระบบตรวจสิทธิ์ก่อนจำโฟลเดอร์ หากรายการภายในไม่ปรากฏให้ตรวจสิทธิ์ของไฟล์เหล่านั้นก่อน ไม่อ้างว่าโฟลเดอร์ว่างหรือไฟล์ถูกลบ
- โปรแกรมไม่ใช้คลังที่กำหนดยกเลิก ไม่อ่าน/สแกนโฟลเดอร์ย่อยที่มี Folder ID ของคลังดังกล่าว
- ไม่ลบหรือรวมไฟล์ต้นฉบับโดยอัตโนมัติ การตรวจซ้ำใช้ MIDI **ภายใน** XMID/XSK ไม่ใช้ชื่อไฟล์หรือ MD5 ของตัวห่อเพียงอย่างเดียว
- การเผยแพร่ฐานใช้การตรวจรุ่นล่าสุด, การล็อกข้ามแท็บและการสำรองฐานเดิม จึงไม่ยอมเขียนทับฐานที่ถูกเปลี่ยนจากอีกเครื่องโดยไม่ตรวจ
- พื้นที่ FX ไม่มีการอัปโหลดอัตโนมัติ ไฟล์ที่เลือกเปิดเล่นชั่วคราวในแท็บเท่านั้น จำกัดขนาดเพื่อไม่ให้หน่วยความจำทำงานหนัก
- ไฟล์เสียง/เพลง/FX ยังเป็นข้อมูลส่วนตัวบน Google Drive; ไม่มีการเก็บ Google access token ในการตั้งค่าโฟลเดอร์

## การทำงานเมื่อสลับแท็บ

งานสร้างฐานจะไม่ถูกยกเลิกเพียงเพราะสลับแท็บ และระบบอัปเดตเว็บจะไม่รีโหลดระหว่างสร้างฐาน ผลตรวจแพ็กเกจที่ผ่านแล้วเก็บเป็น metadata ใน IndexedDB แยกบัญชี คลัง โฟลเดอร์ และ File ID/MD5/ขนาด/ชนิดไฟล์ โดยไม่เก็บเสียงหรือ OAuth token เมื่อกลับมาเปิดแท็บหลังถูกพักหรือรีโหลด ระบบทำงานเดิมต่อหลังยืนยันบัญชี โดยอ่านรายการไฟล์และฐานล่าสุดก่อนเสมอ หากไฟล์เปลี่ยนต้องตรวจใหม่ ปุ่มยกเลิกล้างงานที่รอทำต่อแต่ไม่แตะฐานเดิม Safari/iOS สามารถพัก JavaScript เมื่อสลับแอปหรือล็อกจอได้ จึงไม่รับประกันการทำงานขณะระบบปฏิบัติการระงับแท็บ การทำงานตลอดแม้ปิดแอปต้องมี worker ฝั่งเซิร์ฟเวอร์ที่ได้รับสิทธิ์ Google Drive อย่างเหมาะสม


## ใช้งานร่วมกันระหว่าง Karaoke PC · Karaoke Online · Song Studio Pro

ทุกโปรแกรมเลือก **โฟลเดอร์จริงชื่อ `XStageKaraoke` เดียวกัน** ผ่าน Google Drive for desktop
บน Windows โดยมี `SONGS/`, `SOUNDFONT/`, `FX/` และ `DB/songs.sqlite3`
เป็นโครงสร้างหลัก โฟลเดอร์อื่นที่ยกเลิกแล้วห้ามอ่าน/เขียนและห้ามนำเข้าอัตโนมัติ

### Karaoke PC เมื่อเลือก Google Drive

เมนู **เพลง → Google Drive · ใช้ DB/songs.sqlite3 ร่วมกับ Online** เปิด
`XStageKaraoke/DB/songs.sqlite3` จากไดรฟ์ที่ซิงก์อยู่บน PC **โดยตรงแบบ Read-only**.
ไฟล์นี้เป็น SQLite snapshot ตาม schema `xstage-sqlite3-v1`, ซึ่งไม่ใช่ schema ของ
SQLite ภายในเครื่องเล่น PC จึงห้ามเปิดด้วย `SongLibrary` ที่จะเปลี่ยนตาราง
เปิด WAL หรือสร้างฐานว่างแทนเมื่อหาไฟล์ไม่พบ ตัวอ่านใหม่นี้ตรวจ schema,
`PRAGMA quick_check`, ค้นหาชื่อ/รหัส/ศิลปิน และหาพาธเพลงภายใน
`XStageKaraoke/SONGS` อย่างเคร่งครัด ถ้ายังไม่ซิงก์ไฟล์ลงเครื่องจะแจ้งว่า
ยังเล่นไม่ได้ ไม่เดาพาธจากชื่อเพลง

เมื่อเลือกเพลงเพื่อเล่น PC ใช้ข้อมูลรายการจาก SQLite ของ Drive ผ่าน
ช่องเล่นเพลงชั่วคราวในหน่วยความจำ **ไม่เพิ่มแถวเพลงลงฐาน PC อีกชุด**
และไม่เขียนฐาน Online การตั้งค่าภายใน PC/คิวเฉพาะเครื่องยังแยกจาก
ฐานร่วมและไม่ได้ย้ายไป Drive

เมนู **เพลง → Google Drive · ส่งเพลง/SoundFont/FX จากเครื่อง** มีสองขั้นตอน
ตรวจ SHA-256/ไฟล์ซ้ำก่อน และผู้ใช้กดยืนยันส่งเฉพาะไฟล์ใหม่ไปยังโฟลเดอร์
Google Drive **บนเครื่อง**. คำสั่งส่งไม่มีสิทธิ์แก้ `DB/songs.sqlite3`
และไม่ลบต้นฉบับหรือไฟล์เดิม การยกเลิกเก็บไฟล์ที่ส่งสำเร็จแล้วไว้

### Song Studio Pro

เมนู Google Drive มีการเลือกต้นทาง/ปลายทาง, หมวด `SONGS/SOUNDFONT/FX`,
คำสั่งตรวจรายการก่อนส่ง และยืนยันส่งผ่าน backend ที่ทำงานในเครื่อง
โดยแยก SQLite สำหรับตัดต่อ/ผลิตเพลงออกจากฐานเพลงหลักบน Drive

### Karaoke Online

รอ Google Drive for desktop ซิงก์ไฟล์ขึ้นคลาวด์เสร็จจริงก่อน จากนั้นใช้
**จัดการคลัง Google Drive → ตรวจไฟล์และอัปเดตฐานเพลง** เพื่อตรวจ
MIDI ภายใน XMID/XSK ซ้ำและสร้าง/เผยแพร่ `DB/songs.sqlite3` ตาม
กลไกสำรองและตรวจความสอดคล้องเดิม ห้ามให้ PC/Studio เขียน SQLite พร้อมกัน
หรือ copy SQLite ที่เปิด WAL อยู่ทับไฟล์ฐานหลัก

### ขอบเขตการลบเพลงซ้ำ

- การส่งไฟล์: SHA-256 ทั้งไฟล์ใช้ข้ามไฟล์ที่ซ้ำกัน; ไฟล์ชื่อชนแต่เนื้อหาแตกต่าง
  เป็น **Conflict** ต้องตรวจเอง ไม่เขียนทับ
- การสร้างฐาน Online: ตรวจ MIDI ภายใน XMID/XSK อีกชั้นเพื่อป้องกัน
  เพลงเดียวกันซ้ำในฐาน
- **ยังไม่ลบไฟล์จริงจาก Google Drive อัตโนมัติ** เพราะต้องตรวจว่าแค็ตตาล็อก
  อ้างอิง File ID ใดและไฟล์ประกอบถูกใช้อยู่หรือไม่ ควรมีขั้นตอน
  ตรวจรายการ/เลือกไฟล์หลัก/ส่งเข้า Recycle Bin หรือ BACKUP ก่อนลบถาวร
- งานบนโฟลเดอร์ Drive for desktop แสดงสถานะเพียงว่าเขียนไฟล์ลงไดรฟ์
  บนเครื่องสำเร็จ ไม่ได้อ้างว่าอัปโหลดขึ้นคลาวด์เสร็จจนกว่า Drive client จะยืนยัน

ข้อจำกัดที่ต้องทดสอบเพิ่มเติม: True Windows Google Drive streaming/mirror mount,
ล็อกไฟล์ SQLite ขณะ Drive กำลังปรับปรุง, การเปิด XMID/XSK บนระบบเสียงจริง,
เพลงที่มี `original_relative_path` ไม่ตรงกับไฟล์ในเครื่อง, และความครบถ้วนของ
ไฟล์ประกอบ NCN (MID/LYR/CUR). ยังไม่ถือว่าพร้อมออกรุ่น EXE จนกว่า Windows CI
และการทดสอบกับ Google Drive จริงจะผ่าน
